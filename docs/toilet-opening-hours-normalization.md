# 화장실 개방시간 정형화 초안

## 결론

`toilet.open_time`과 `toilet.open_time_detail`은 번역 문자열로 복제하지 않는다. 두 필드는 공공데이터 원문으로 보존하고, 검색·필터·다국어 표시는 별도 정형 결과에서 만든다.

## 실제 데이터 표본

2026-09-20 공개 상세 API의 전국 분산 표본을 확인했다. 500건을 요청했고 API 제한과 현재 공개 상태 차이로 201건을 응답받았다. 운영 DB 읽기 전용 집계가 가능해지면 전체 데이터를 다시 검증한다.

`open_time` 분포:

| 값 | 건수 |
| --- | ---: |
| 정시 | 97 |
| 상시 | 79 |
| 미입력 | 21 |
| 미개방 | 2 |
| 불규칙 | 2 |

`open_time_detail`에는 `09:00~18:00`, `24시간`, `00:00~24:00`, `00~24`, `연중무휴`, 요일별 시간, 휴관일, 계절 조건이 혼재했다. 다음 충돌 사례도 확인했다.

- `상시`이지만 상세가 `10:30~21:00`
- `정시`이지만 상세가 `24시간`
- `open_time`이 비어 있고 상세만 `24시간`
- `미개방`이지만 상세가 `월~금 09시~18시`

따라서 `open_time='상시'`만으로 24시간 운영을 확정하지 않는다.

## 제안 구조

원문은 기존 `toilet`에 유지하고 정형 결과를 별도 테이블에 둔다.

- `opening_policy`: `ALWAYS`, `SCHEDULED`, `IRREGULAR`, `CLOSED`, `UNKNOWN`
- `is_open_24h`: `TRUE`, `FALSE`, `NULL`의 3상태
- `normalization_status`: `PARSED`, `REVIEW_REQUIRED`, `CONFIRMED`
- `parser_version`, `confidence`, `normalized_at`, `confirmed_by_user_id`, `confirmed_at`
- 요일별 시작·종료 시각과 휴무 여부
- 계절·공휴일·임시 예외는 별도 규칙 또는 검토 사유로 보존

## 판정 우선순위

1. 관리자 확정값
2. 상세 문구의 명시적 시간·휴무 규칙
3. `open_time` 상태값
4. 판정 불가 시 `UNKNOWN` 또는 `REVIEW_REQUIRED`

`24시간`, `00:00~24:00`, `00:00~23:59`처럼 하루 전체 운영이 명시된 문구만 자동으로 24시간 후보가 된다. `연중무휴`는 휴무일이 없다는 뜻일 뿐 운영 시간이 하루 전체라는 뜻은 아니므로, 시간 범위가 함께 확인되지 않으면 24시간으로 판정하지 않는다. `상시`이고 상세가 비어 있는 항목도 높은 신뢰도의 후보로만 분류하고 전체 데이터 검증 전에는 확정하지 않는다. 계절 제한이나 특정 요일 휴무가 있으면 24시간 필터에서 제외하거나 조건부 운영으로 표시한다.

## 다국어 표시

정형 결과를 UI 번역 키로 조립한다.

- `is_open_24h=TRUE` → `24시간 운영` / `Open 24 hours`
- 평일 일정 → `평일 09:00–18:00` / `Weekdays 09:00–18:00`
- 검토 필요 → 원문을 한국어로 표시하고 번역 완료로 간주하지 않는다.

이 구조를 사용하면 24시간 필터와 한국어·영어 화면이 같은 판정값을 공유한다.
