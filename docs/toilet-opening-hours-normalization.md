# 화장실 개방시간 정형화 계약

## 결론

`toilet.open_time`과 `toilet.open_time_detail`은 번역 문자열로 복제하지 않는다. 두 필드는 공공데이터 원문으로 보존하고, 검색·필터·다국어 표시는 별도 정형 결과에서 만든다.

## 실제 데이터 표본

2026-09-20 공개 상세 API의 전국 분산 표본을 확인했다. 500건을 요청했고 API 제한과 현재 공개 상태 차이로 201건을 응답받았다. 운영 DB 읽기 전용 집계가 가능해지면 전체 데이터를 다시 검증한다.

`open_time` 분포:

| 값 | 건수 |
| --- | ---: |
| 정시 | 97 |
| 상시 | 79 |
| 미입력 | 21 |
| 미개방 | 2 |
| 불규칙 | 2 |

`open_time_detail`에는 `09:00~18:00`, `24시간`, `00:00~24:00`, `00~24`, `연중무휴`, 요일별 시간, 휴관일, 계절 조건이 혼재했다. 다음 충돌 사례도 확인했다.

- `상시`이지만 상세가 `10:30~21:00`
- `정시`이지만 상세가 `24시간`
- `open_time`이 비어 있고 상세만 `24시간`
- `미개방`이지만 상세가 `월~금 09시~18시`

따라서 `open_time='상시'`만으로 24시간 운영을 확정하지 않는다.

## 제안 구조

원문은 기존 `toilet`에 유지하고 정형 결과를 별도 테이블에 둔다.

- `opening_policy`: `ALWAYS`, `SCHEDULED`, `IRREGULAR`, `CLOSED`, `UNKNOWN`
- `is_open_24h`: `TRUE`, `FALSE`, `NULL`의 3상태
- `normalization_status`: `PARSED`, `REVIEW_REQUIRED`, `CONFIRMED`
- `parser_version`, `confidence`, `normalized_at`, `confirmed_by_user_id`, `confirmed_at`
- 요일별 시작·종료 시각과 휴무 여부
- 공휴일 정책은 `holiday_policy`로 저장하고, 계절·임시 예외는 원문과 검토 상태로 보존

정형 결과에는 한국어 문장을 저장하지 않는다. `toilet_opening_hours`에는 정책·24시간 여부·판정 상태만 저장하고, `toilet_opening_schedule`에는 ISO 요일 번호(월요일 1~일요일 7), 시작·종료 시각, 익일 종료 여부를 저장한다. 기존 `toilet.open_time`과 `toilet.open_time_detail`은 수신 증거와 새 파서 재실행을 위해 유지한다.

## 판정 우선순위

1. 관리자 확정값
2. 상세 문구의 명시적 시간·휴무 규칙
3. `open_time` 상태값
4. 판정 불가 시 `UNKNOWN` 또는 `REVIEW_REQUIRED`

`24시간`, `00:00~24:00`, `00:00~23:59`처럼 하루 전체 운영이 명시된 문구만 자동으로 24시간 후보가 된다. `연중무휴`는 휴무일이 없다는 뜻일 뿐 운영 시간이 하루 전체라는 뜻은 아니므로, 시간 범위가 함께 확인되지 않으면 24시간으로 판정하지 않는다. `상시`이고 상세가 비어 있는 항목도 높은 신뢰도의 후보로만 분류하고 전체 데이터 검증 전에는 확정하지 않는다. 계절 제한이나 특정 요일 휴무가 있으면 24시간 필터에서 제외하거나 조건부 운영으로 표시한다.

## 다국어 표시

정형 결과를 UI 번역 키로 조립한다.

- `is_open_24h=TRUE` → `24시간 운영` / `Open 24 hours`
- 평일 일정 → `평일 09:00–18:00` / `Weekdays 09:00–18:00`
- 검토 필요 → 원문을 한국어로 표시하고 번역 완료로 간주하지 않는다.

이 구조를 사용하면 24시간 필터와 한국어·영어 화면이 같은 판정값을 공유한다.

## 예외 정보의 스키마 경계

정형 스키마 v1은 반복 가능한 주간 일정과 공휴일 운영 정책까지 확정한다. 계절별 운영시간은 시작일과 종료일이 공공데이터에 일관된 구조로 제공되지 않으므로 원문을 보존하고 `REVIEW_REQUIRED`로 보낸다. 임시 휴무는 공공데이터의 시설 속성이 아니라 시점에 따라 바뀌는 운영 상태이므로 영구 주간 일정에 합치지 않는다. 향후 임시 휴무를 제공할 때는 적용 시작·종료 시각과 근거를 갖는 별도 가용성 이벤트로 저장한다.

따라서 현재 계약은 다음과 같다.

- 주간 반복 일정: `toilet_opening_schedule`
- 24시간 여부와 기본 운영 정책: `toilet_opening_hours`
- 공휴일: `holiday_policy`의 `OPEN`, `CLOSED`, `UNKNOWN`
- 계절 조건: 원문 보존 후 관리자 검토, 자동 확정 금지
- 임시 휴무: 원문 보존 후 관리자 검토, 주간 일정에 저장 금지

이 경계는 계절 문구나 임시 휴무가 영구적인 24시간 필터에 잘못 포함되는 일을 막는다.

## 구현 계약

- V27은 두 정형 테이블을 만들고, 원문 전체가 명시적인 24시간 표현이거나 명백한 미개방인 항목만 보수적으로 최초 판정한다.
- Java 파서 v1은 명시적 24시간, 단일 시간 범위, 평일·주말·특정 요일, 익일 종료를 언어 중립 값으로 변환한다.
- `연중무휴` 단독, `상시` 단독, 복수 시간대, 계절·공휴일 예외, 상태와 상세가 충돌하는 항목은 `REVIEW_REQUIRED`로 남긴다.
- 관리자 재처리 API는 식별자 커서 방식으로 최대 1,000건씩 안전하게 백필한다.
- 관리자가 확정한 값은 `manual_override=TRUE`로 보호한다. 이후 원문이 바뀌면 값을 덮어쓰지 않고 `source_changed=TRUE`로 표시한다.
- 공개 상세 응답은 원문과 함께 `normalizedOpeningHours`를 제공한다. 화면은 정형 코드를 locale별 번역 키로 표시한다.
- 지도 조회의 `open24h=true`는 `PARSED` 또는 `CONFIRMED`, `is_open_24h=TRUE`, `source_changed=FALSE`인 항목만 반환한다.
- 공공데이터 배치는 화장실 삽입·갱신 직후 같은 파서 버전으로 정형 결과를 동기화한다. 원문 해시와 파서 버전이 모두 같으면 재정형과 캐시 갱신을 생략한다.
- `Opening hours production audit` 워크플로는 운영 DB 전체의 정형 행 누락, 24시간 판정 근거, 일정 일관성을 읽기 전용으로 검사한다.
