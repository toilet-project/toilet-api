# 사용자 닉네임 수정 (WEB #192)

- `PATCH /api/v1/auth/me/profile`, JSON `{ "displayName": "새 닉네임" }`
- HttpOnly access cookie 또는 기존 Bearer 인증 사용. 사용자 ID는 JWT subject에서만 결정한다. 다른 사용자 ID, 역할, 이메일을 수정할 수 없다.
- ACTIVE 계정만 허용. 익명/존재하지 않는 사용자 401, 비활성 계정 403, 형식 오류 400.
- 앞뒤 공백 제거 및 NFC 정규화 후 2~30 UTF-16 코드 단위. 제어 문자, 방향 제어 문자 등 FORMAT 문자, 공백만 있는 이름 금지. 닉네임은 식별자가 아니며 중복 허용.
- 기존 `app_user.display_name`에 트랜잭션으로 저장한다. DDL/새 컬럼/데이터 일괄 변경 없음.
- 표시 이름은 가입 시 소셜 제공자 이름으로 초기화하고, 이후 사용자 관리 값으로 취급한다. 소셜 재로그인은 비어 있는 이름만 보충한다. 이메일·이메일 인증 상태·로그인 시각의 기존 재평가는 유지한다.
- 사진 URL을 저장/조회하는 기존 API 필드가 없어 웹에는 기본 원형 아바타를 표시한다. 사진 업로드/소셜 사진 수집은 이번 범위에 없음.
- 응답은 `displayName`만 포함하며 로그에 입력 이름을 추가하지 않는다. 인증 오류 시 프론트는 저장 성공으로 표시하지 않는다.

## 검증

- 인증/닉네임 테스트: 유효 값, 빈 값·과다 길이·제어 문자, 비활성·탈퇴 계정 차단, JWT subject만 사용, 로그인 후 변경 이름 유지.
- 로컬 전체 테스트는 Docker 미실행에 따른 MySQL 통합 테스트 실패와 기존 H2에서의 MySQL DDL 문법 실패가 있다. 전체 통과로 간주하지 않는다.
- 운영 계정/운영 DB에 대한 테스트 수정 없음. 배포 시 API를 먼저 반영한 다음 웹 UI를 반영해야 한다.
