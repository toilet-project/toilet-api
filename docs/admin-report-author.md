# 관리자 제보 상세 작성자 표시

## 범위

관리자 전용 `GET /api/admin/v1/reports/{reportId}` 응답 최상위에
`reporterDisplayName` 문자열을 추가한다. 기존 `report`, `toilet` 구조는 유지한다.
관리자 상세 제목 아래에 표시하며, 공개 API·내 제보 응답·대시보드·검색 목록에는 추가하지 않는다.
기존 `/api/admin/**`의 ADMIN 권한 검사를 유지한다.

## 표시 규칙

| 현재 DB 상태 | 표시 |
| --- | --- |
| 회원 연결 존재, WITHDRAWN 아님 | 현재 display_name; 비어 있으면 ‘급똥 사용자’ |
| 회원 상태 WITHDRAWN | 저장된 이름과 무관하게 ‘탈퇴한 사용자’ |
| 개인정보 파기로 reporter_user_id가 NULL | ‘탈퇴한 사용자’; 회원 조회하지 않음 |
| 회원 ID는 남아 있지만 해당 회원이 없음 | ‘작성자 정보 없음’; 탈퇴라고 추정하지 않음 |

복구·닉네임 변경 후 다음 상세 조회에서 현재 이름을 조회한다.
제보에 이름을 복사하거나 보관용 닉네임을 복호화하지 않는다.
회원 ID·이메일·소셜 ID·인증 버전은 응답에 추가하지 않는다.
목록의 회원별 추가 조회는 없고, 상세 한 건에서만 회원 조회 최대 한 번을 추가한다.

## 변경하지 않는 것

DDL, 기존 제보/사유/감사 로그, 탈퇴·복구·파기 규칙, 계정 활성 설정,
승인·반려 및 좌표 변경, 배치·백업·대장 종료는 변경하지 않는다.
회원 파기 시 제보의 개인정보가 제거되는 기존 규칙은 그대로 유지한다.

## 호환 및 인수

API 먼저 배포하고 관리자 화면을 뒤이어 배포한다. 구 관리자 화면은 추가 필드를 무시한다.
새 관리자 화면이 구 API 응답을 받으면 ‘작성자 정보 없음’으로 표시한다.
이름은 HTML 이스케이프하고 긴 문자열은 줄바꿈한다.

합성 검증: 현재 닉네임 변경, 탈퇴 상태의 잔여 이름 숨김, 명시 복구,
파기된 연결, 불일치 연결, 빈 이름, JSON 노출 범위, 목록 조회 영향,
관리자 상세 상태별 표시/닫기 및 HTML 입력 처리.

실제 운영 작성자 표시 인수는 배포 후 별도 확인한다. 합성 테스트를 실제 탈퇴 검증으로 대체하지 않는다.
실계정 탈퇴·보관 철회·파기는 별도 승인 없이 실행하지 않는다.
