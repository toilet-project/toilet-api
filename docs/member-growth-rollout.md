# 회원 성장·배지 적용 안내

## 목적과 현재 상태

리뷰 기여를 경험치와 지역 배지로 기록하고 마이페이지에서 확인한다. 출시 전 리뷰도 같은 기준으로 소급한다. 운영 서버와 복원 도구를 적용했고, 지급 정책을 고정한 뒤 기존 리뷰의 경험치를 소급 지급했다. 최종 원장·백업 복원 검증과 사용자 화면 공개의 최신 진행 상태는 [WBS 121](https://github.com/toilet-project/docs/issues/121)에서 관리한다.

## 지급 기준

| 활동 | 경험치 | 중복 방지 기준 |
| --- | ---: | --- |
| 유효한 첫 화장실 리뷰 | 10 | 회원·화장실별 한 번 |
| 하루 접속 | 2 | 회원·한국 날짜별 한 번, 과거 접속 소급 없음 |
| 동네 배지 | 20 | 대상 시·군·구의 유효 화장실 리뷰 1곳 |
| 지역 동메달 | 30 | 서로 다른 화장실 3곳, 동네 1곳 |
| 지역 은메달 | 50 | 화장실 10곳, 대상 동네 50% 이상(올림) |
| 지역 금메달 | 100 | 화장실 30곳, 대상 동네 전체 |

레벨 L의 누적 경험치는 `max(0, 10 × (L² − 1))`이다. 휴지 등급 시작 레벨은 흰색 1, 초록 3, 노랑 5, 파랑 10, 빨강 15, 핑크 25, 검정 40이다. 광고 보상은 포함하지 않는다.

## 데이터와 개인정보

- `growth_xp_event`에 지급·회수를 기록하고 `growth_account`에 합계를 보관한다. 지급 원장을 임의 수정해 합계를 맞추지 않는다.
- `growth_award`의 회원·보상 종류·대상으로 중복 지급을 막는다. 기준 버전을 바꿔 같은 기여를 다시 지급하지 않는다.
- 기준과 대상 동네는 `growth_policy_snapshot`, `growth_policy_target`에 고정한다. 기준 변경만으로 기존의 정상 보상을 회수하지 않는다.
- 리뷰 연결 해제·부정 리뷰 제외는 남은 기여와 최초 지급 기준으로 다시 계산한다. 다른 유효 리뷰가 같은 시설에 남으면 그 시설 기여는 유지한다.
- 연결이 끊어진 리뷰는 성장 근거에서도 제거한다. 더 이상 유효하지 않은 지급 대상 연결 키도 지운다. 익명 리뷰에서 작성자를 추정하지 않는다.
- 탈퇴 유예 기간에는 기존 복구 정책을 따르고, 회원 최종 삭제 시 개인 성장 자료도 함께 삭제한다. 백업 복원 시 새 복원 도구로 연결 해제를 재적용해야 한다.
- 기존 리뷰에는 원시 위치 검사 기록이 없다. 등록 요청 연결과 해당 기간의 서버 등록 경로를 확인한 리뷰만 소급한다. 현재 시설 좌표로 과거 방문 여부를 재구성하지 않는다.
- 지역을 확인할 수 없는 리뷰는 리뷰 경험치만 계산하고 지역 수집은 보류한다.

## API

회원 API는 현재 회원 상태·인증 버전·정책 동의를 검사한다. 개인 응답은 캐시하지 않는다.

| 경로 | 역할 |
| --- | --- |
| `GET /api/v1/growth/me` | 경험치, 등급, 배지, 지역 진행 상황 |
| `POST /api/v1/growth/check-in` | 한국 날짜 기준 접속 보상 |
| `GET /api/v1/growth/history` | 최근 50건 지급·회수 내역, 기존 `{items}` 응답 유지 |
| `GET /api/v1/growth/history?direction=earned&page=0&size=10` | 전체 지급·회수 내역을 방향별로 페이지 조회 |

경험치 내역 페이지 조회는 코드·테스트 준비 단계이며 운영 반영 전이다. `direction`, `page`, `size` 중 하나라도 지정하면 `{items,total,page,size}`를 반환한다. `direction=earned`는 양수 경험치, `deducted`는 음수 경험치만 조회하며 방향 생략 시 양쪽을 포함한다. `page`는 0부터 시작하고 기본값은 0, `size` 기본값은 10이며 1~50만 허용한다. 잘못된 방향·페이지·개수는 400 응답이고, 마지막 페이지를 넘으면 전체 수를 유지한 빈 `items`를 반환한다.

행과 전체 수는 로그인한 회원의 실제 경험치 원장에만 한정하고 `event_id` 내림차순으로 조회한다. `type`은 `EARN`·`REVOKE`이며 방향은 경험치 증감 부호로 판정한다. 조회 중 소급 지급·재계산·접속 보상을 실행하지 않는다. 기능이 꺼졌거나 정책이 초기화되지 않았다면 빈 내역을 반환하되 계정 상태·인증 버전·동의 검사는 유지한다. 캐시 금지 정책과 기존 무쿼리 응답은 동일하다. 새 기록이 추가되면 다음 요청의 페이지 위치와 전체 수는 바뀔 수 있다.

`happenedAt`은 한국 시간의 오프셋 없는 날짜·시간이다. 응답의 `reason`은 기여가 반영된 계기이며 개별 리뷰·배지·메달의 종류가 아니다. 프런트는 알려지지 않은 사유에도 일반적인 내역 문구를 표시해야 한다.

관리 API는 토큰 권한과 현재 관리자 권한을 모두 검사한다. 쓰기 요청은 기존 출처 검사도 적용한다.

| 경로 | 역할 |
| --- | --- |
| `GET /api/admin/v1/growth/policy/preview` | 기준 및 대상 수 확인, 쓰기 없음 |
| `POST /api/admin/v1/growth/policy/initialize` | `{policyVersion}`으로 대상 목록 최초 고정 |
| `GET /api/admin/v1/growth/backfill/candidates?afterUserId=0&size=50` | 활성 회원을 최대 50명씩 조회 |
| `GET /api/admin/v1/growth/users/{userId}/preview` | 지급 전 대상과 예상 증감 확인, 쓰기 없음 |
| `POST /api/admin/v1/growth/users/{userId}/apply` | `{policyVersion}`으로 해당 회원 소급 적용 |
| `POST /api/admin/v1/growth/reviews/{reviewId}/eligibility` | `{excluded,reason}`으로 기여 제외·복구 |

미리 계산한 결과와 실제 지급 사이에 리뷰가 바뀔 수 있다. 지급은 회원 잠금 안에서 최신 상태로 재계산한다. 중단 후 같은 회원을 재처리해도 정당한 보상 잔액만 남는다.

회원 미리보기의 `linkedReviews`는 현재 연결된 리뷰 수, `excludedReasons`는 등록 근거 없음·운영 제외·필수 평가 오류·비공개 시설의 사유별 수다. 여러 사유에 해당하면 한 가지로 집계한다. `pendingRegionFacilities`는 지역 수집을 보류한 시설 수다. 익명 리뷰를 개인에게 다시 연결해 제외 수를 추정하지 않는다.

## 운영 적용 순서

1. 기존 등록 요청 근거·배포 기간, 지역별 대상 목록, 리뷰 제외 기준을 운영 데이터로 확인한다. 운영 DB 백업과 복원 도구의 호환 여부도 확인한다.
2. API와 배치의 공용 성장 복원 코드가 일치하는 새 복원 도구를 먼저 준비한다. V40 이후 백업에 이전 복원 도구를 사용하지 않는다.
3. V40과 API를 배포한다. `GROWTH_ENABLED=false`, 웹 `NEXT_PUBLIC_GROWTH_ENABLED=false` 상태를 유지한다.
4. 관리자 미리보기로 대상 수와 대표 회원을 검토한 뒤 정책을 최초 고정한다. 미리보기 호출 자체는 데이터를 생성하지 않는다.
5. 웹 표시는 끈 채 `GROWTH_ENABLED=true`로 신규 리뷰의 실시간 처리를 시작한다. 이 상태에서 회원 목록을 순회해 미리 계산·소급 지급한다. 신규 활동과 소급은 같은 회원 잠금·중복 기준을 사용한다.
6. 제외·보류 항목과 원장 합계, 성장 합계, 실제 지급 결과를 대조한다. 실패한 회원만 다시 실행할 수 있다.
7. 검증 후 웹 표시를 켠다. 탈퇴·익명 전환·복원 경로도 새 도구로 유지한다.

문자 정렬 호환성을 수정한 뒤 새 백업을 만들고, 격리 복원까지 통과한 백업만 기준으로 사용한다.

문제가 있으면 먼저 기능 표시와 신규 지급을 끈다. 개인정보 연결 해제는 기능이 꺼져도 계속 처리한다. 원장이나 적용된 마이그레이션을 삭제해 되돌리지 않는다.

### 운영 호스트 실행

API와 배치 이미지는 승인된 커밋으로 고정한 뒤, 운영 호스트의 기존 배포 계정에서 검토된 `scripts/growth_release_transition.py`를 직접 실행한다. `--api-commit`과 `--batch-commit`에는 각각 실행 중인 이미지의 정확한 커밋을 넣는다. 스크립트는 공용 유지보수 잠금을 잡고 이미지·설정·상태를 검사하며, 쓰기 단계에는 배포 중지 확인과 `--apply-approved`가 필요하다. 비밀번호나 환경 파일 내용은 명령에 넣지 않는다.

1. `--operation check`로 현재 상태와 이미지 고정을 확인한다.
2. `--operation mount-disabled --apply-approved --deployment-freeze-confirmed`로 기존 설정을 보존한 채 성장 기능을 끈 상태로 탑재한다.
3. API 컨테이너의 `/app/growth-ops.jar policy-preview` 결과에서 버전·16개 권역·대상 구 수·목록 지문을 확인하고, 같은 값으로 `policy-initialize VERSION TARGETS 16 DIGEST --apply`를 한 번 실행한다. 미리보기는 읽기 전용이다.
4. `--operation activate --apply-approved --deployment-freeze-confirmed`로 서버 지급을 켠다. 그 전에 운영 미리보기의 제외 사유를 확인한다.
5. CLI `batch-preview AFTER SIZE`로 최대 50명씩 검토하고 제외 건수를 확인한 후 `batch-apply VERSION AFTER SIZE EXPECTED_EXCLUDED --apply`를 실행한다. 반환된 다음 커서로 순회하며, 마지막에 `ledger-check`로 원장·잔액·리뷰 연결 건수를 대조한다.
6. 지급을 멈춰야 하면 `--operation deactivate --apply-approved --deployment-freeze-confirmed`를 실행한다. 이 작업은 기존 지급 내역을 삭제하지 않는다.

각 단계의 실제 실행·결과는 배포 기록에 남긴다. 실패 시 다음 단계로 넘어가기 전에 상태를 다시 검사한다.

## 완료 판단

운영 완료·남은 작업과 실제 회원 화면 공개 여부는 [WBS 121](https://github.com/toilet-project/docs/issues/121)의 최신 체크리스트를 따른다.

## 로컬 검증 결과

- 실제 MySQL에서 V17·V40을 적용해 16권역, 세종, 이전 지역 코드, 소급과 연결 해제의 동시 처리를 확인했다.
- MySQL 8의 서로 다른 리뷰 키 문자 정렬에서 기존 비교 오류를 재현하고, V41 적용 후 기존 키·경험치를 보존하며 비교가 성공하는지 확인했다.
- 지급 멱등성, 한국 날짜 출석, 기존 기준과 보상량 유지, 회수·원천 연결 정리, 탈퇴 보관·최종 삭제를 검증했다.
- API·배치 공용 코드 계약과 복원 도구 패키징을 확인했고, 배치 [PR 69](https://github.com/toilet-project/toilet-batch/pull/69)의 CI가 통과했다.
- 웹 타입·관련 테스트·프로덕션 빌드가 통과했다. 가상 회원의 실제 서버 계산을 브라우저에 연결해 경험치·등급·배지·계산기·헤더/본문 정렬을 확인했다. 실제 회원의 프로필 변경이나 사진 업로드는 수행하지 않았다.
- 격리된 HTTP 검증 호스트와 로컬 프록시는 테스트 전용이다. 운영 인증이나 배포 경로로 사용하지 않는다.
