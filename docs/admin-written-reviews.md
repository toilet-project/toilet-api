# 관리자 작성 리뷰 모니터링

관리자 서비스 이용분석의 ‘작성 리뷰’ 탭에서 등록된 리뷰를 읽기 전용으로 조회한다. 최신순 목록과 선택한 리뷰의 상세를 분리해 본문을 한꺼번에 전송하지 않는다.

## API 계약

- `GET /api/admin/v1/reviews?size=20&cursor=...`: `{items,nextCursor,hasMore}`. 기본 20개, 최대 50개. 전체 건수 조회 없이 `created_at DESC, review_id DESC` 키셋 페이지로 조회한다.
- 목록 항목: `id`(문자열), `toiletId`, `toiletName`, `toiletVisibility`, `satisfaction`, `cleanliness`, `paper`, `waitMinutes`, `authorDisplayName`, `authorRemoved`, `createdAt`, `updatedAt`, `hasComment`.
- `GET /api/admin/v1/reviews/{id}`: 목록 항목과 동일한 필드에 `comment`를 추가한다. 리뷰 본문은 평문이다.
- 만족도·청결도는 각각 1~5점이며 평균은 두 값의 산술평균이다. 휴지 여부는 boolean, 대기는 0~60분의 10분 단위 정수다.
- 시각은 기존 리뷰 저장 규칙에 맞춰 KST `+09:00`를 명시하며 마이크로초를 유지한다. 커서는 권한 토큰이 아니고 정렬 위치일 뿐이다.
- 세션 만료 401, 현재 관리자 권한 없음 403, 잘못된 조회 조건 400, 없는 리뷰 404. 성공·실패 모두 `Cache-Control: private, no-store`를 적용한다.

## 보존과 권한

매 요청에서 기존 ADMIN JWT 경계와 현재 계정 활성 상태·인증 버전·DB ADMIN 역할을 모두 확인한다. 목록·상세 모두 개인정보 연락처·계정 ID·작성 당시 위치·사진 키를 전송하지 않는다.

작성자 연결 해제 리뷰는 ‘익명’, 탈퇴·삭제 계정은 ‘탈퇴한 사용자’로 보인다. 비활성 계정 이름도 표시하지 않는다. 숨김 화장실의 기존 리뷰는 유지하고 `toiletVisibility`로 구분한다. 현재 리뷰에는 별도 삭제·숨김 상태가 없으며 이 기능은 수정·삭제·작성자 복구를 제공하지 않는다. 리뷰 작성 기능을 일시 중지하더라도 관리자의 기존 리뷰 모니터링은 유지된다.

## DB 인덱스와 운영 적용 제한

현재 기존 인덱스는 작성자 또는 화장실 ID가 선두인 복합 인덱스다. 전체 최신순 목록을 위해 `V45__index_admin_review_created.sql`은 `(created_at, review_id)` 인덱스만 추가한다. 기존 레코드·본문·작성자 연결은 바꾸지 않는다. 쿼리는 인덱스 없이도 동작하지만 데이터가 늘면 정렬 비용이 증가할 수 있다.

이 변경의 운영 API 배포와 Flyway 실행은 별도 승인 대상이다. 프리뷰 검수 작업은 운영 DDL을 실행하지 않는다. 실제 운영 DB 읽기 전용 점검에서는 리뷰 20개와 기존 작성자·화장실별 인덱스를 확인했다. 현재 전체 최신순 조회는 리뷰 20개를 정렬하고 화장실·작성자를 PK로 조인하므로 프리뷰에서 실행할 수 있다. 리뷰가 증가할 때의 정렬 비용을 줄이는 V45 인덱스는 운영 적용 전 단계다.

## 프리뷰

검수 화면은 `https://preview.geupddong.com`에 연결한다. 운영 API 배포 전에는 기존 DB 호스트에 별도 한시 Java 프로세스를 실행하고 실제 `AdminReviewRepository`와 `AdminReviewService`로 요청 시 운영 리뷰를 조회한다. 응답은 관리자 브라우저로 중계하며 리뷰·작성자 원문을 로컬 파일이나 복제 DB로 저장하지 않는다. 기존 운영 API 컨테이너·스키마·역할·권한은 변경하지 않는다.

명시적 전용 빌드 `scripts/written-reviews-live-preview.init.gradle`의 `writtenReviewsLivePreviewJar` 작업은 별도 `written-reviews-live-preview.jar`를 만든다. 운영 앱용 `bootJar`에는 이 서버가 포함되지 않는다. 전용 진입점은 Spring 애플리케이션을 시작하지 않으므로 Flyway·Redis·예약 작업도 실행하지 않는다. 운영 DB 접속 정보는 DB 호스트 안에서만 기존 설정을 사용한다.

매 연결은 MySQL 세션 기본을 `TRANSACTION READ ONLY`로 설정하고 실제 설정값을 확인한 뒤 노출한다. 추가 JDBC 경계는 실제 목록·다음 목록·상세의 정확한 SELECT 3종만 허용하며 쓰기·임의 SQL·권한 변경·다중 문장·연결 우회를 차단한다. 최대 4개 연결, 쿼리 3초, 접속 3초·소켓 5초 제한을 적용한다. 연결마다 별도 세션을 열어 운영 세션의 설정은 바꾸지 않는다.

외부 gateway는 매 요청 실제 관리자 인증을 확인한 뒤 일회용 키로 GET 목록·상세만 중계한다. 한시 서버의 `/__ready`도 키가 있어야 읽을 수 있으며 원문이나 접속 정보를 반환하지 않는다. 컨테이너 내부 바인딩 주소와 무관하게 호스트 포트는 loopback으로만 게시한다. 절대 만료 시각은 최대 2시간이고 서버 자체 종료·호스트 소유 자원 정리·gateway 만료 차단을 함께 사용한다. 요청·SQL 파라미터·본문·DB 접속 오류 상세는 로그에 남기지 않는다.

검증은 실제 H2와 CI의 격리 MySQL에서 최신순·동일 시각 순서·마이크로초·페이지 중간 추가·익명화·권한 회수·본문 분리를 확인한다. 네이티브 읽기 전용 세션의 쓰기 거부 검증도 격리 MySQL에서만 수행한다. 운영 데이터에는 쓰기 검증을 하지 않는다.
