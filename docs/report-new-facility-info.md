# 신규 시설 제보·승인 정보

## 접수와 승인

회원·비회원 신규 제보는 이름·위치와 선택적인 기본 정보를 접수한다.
접수만으로 공개 시설을 생성하지 않으며 관리자 승인 후 등록한다.
`facilityInfo`는 제보 원문, `confirmedFacilityInfo`는 관리자 확정값이다.
확정값은 전체 스냅샷이며 제보 원문을 덮어쓰지 않는다.

## 개방시간 계약

`facilityInfo.openingHours`에 기존 운영시간 확정 계약을 사용한다.

| 항목 | 저장 규칙 |
| --- | --- |
| 운영 방식 | `ALWAYS` 24시간 / `SCHEDULED` 요일별 / `IRREGULAR` 불규칙 / `CLOSED` 운영 중단 |
| 공휴일 | `OPEN` 운영 / `CLOSED` 휴무 / `UNKNOWN` 미확인 |
| 요일별 시간 | 월요일 1~일요일 7, 같은 요일의 여러 시간대 가능 |
| 익일 종료 | 종료가 시작보다 빠르면 `crossesMidnight=true` |
| 휴무 | `closed=true`, 시작·종료는 null |
| 미입력 요일 | 미확인으로 취급하며 휴무로 추정하지 않음 |

운영 방식이 미확인이면 `openingHours=null`이고 기존 개방시간 문구를 사용한다.
요일별 방식에는 최소 하나의 유효한 시간대가 필요하다. 24시간·불규칙·운영 중단에는
요일별 시간표를 저장하지 않는다. 공휴일의 별도 시간대나 특정 날짜 예외는 이번 범위에 없다.
모든 시각은 한국 현지 시각이며 시간대 자동 변환은 하지 않는다.

접수와 승인 모두 기존 운영시간 검증을 적용한다. 승인 시 `OpeningHoursService.confirm`으로
운영시간·요일별 시간표를 저장하고 관리자 확정 보호(`manual_override`)를 켠다.
잘못된 시간표는 시설 생성 전에 거절되며 이후 오류는 승인 트랜잭션 전체를 롤백한다.
감사 기록의 시간은 ISO 문자열로 저장한다.

## 호환·영향

- 이전 제보 JSON과 운영시간 문구만 있는 요청은 계속 처리한다.
- 구조화된 운영시간이 없는 기존 요청의 중복 접수 식별값을 유지한다.
- 편의시설 미확인(null), 없음(false), 확인된 0개를 구분한다.
- 기존 V42의 nullable 제보 JSON 컬럼을 사용한다. 추가 운영시간 스키마 변경은 없다.
- 공개 데이터 캐시 정책 변경·삭제·예열은 이 작업에 포함하지 않는다.
- 운영 배포는 API → 관리자 → 웹 순서로 별도 승인 후 진행한다.

## 검증

제보·운영시간 회귀 테스트와 실제 HTTP/격리 MySQL 검증을 사용한다.
`scripts/verify-report-facility-info.mjs`는 공개 시설을 읽고 시험 DB에만 쓰며,
네 가지 운영 방식·공휴일·복수 시간대·휴무·익일 종료·잘못된 승인 롤백·원문 보존을 확인한다.
프리뷰 접수도 시험 DB에만 반영한다. 모바일 실기기 최종 검수와 운영 배포는 별도 단계다.
