# 두 시설의 영어·중국어 이름 보정

## 바꾸는 내용

시설 2곳의 영어·중국어 간체 **이름 4개만** 바로잡는다. 주소·좌표·한국어·일본어·중국어 번체·다른 시설은 변경하지 않는다. Baidu 등록 계획과는 별개인 기존 오역 보완이다.

| 시설 | 언어 | 기존 | 보정 |
| --- | --- | --- | --- |
| 어울림 (15060) | 영어 | sit | Eoullim |
| 어울림 (15060) | 중국어 간체 | 坐 | Eoullim |
| 한서교 위 (24858) | 영어 | Han Seo-kyo above | Above Hanseogyo Bridge |
| 한서교 위 (24858) | 중국어 간체 | 上面是韩瑞京 | Hanseogyo 桥上方 |

‘어울림’과 ‘한서교’는 고유명사로 보존한다. 공식 외국어 이름이 확인된 것은 아니므로 추측한 중국어 한자 이름을 사용하지 않는다. ‘위’를 원문 그대로 옮기며 상류·북쪽·입구 등 추가적인 위치를 단정하지 않는다.

## 안전 조건

- 현재 한국어 원문과 해시, 기존 번역 이름, 주소 해시, 버전, 번역 출처, 수동 보정 여부가 사전 확인값과 **4행 모두 일치해야** 수정한다. 하나라도 바뀌었거나 누락되면 0행 처리한다.
- 실제 원본·한국어 번역·대상 번역 행을 잠근 뒤 확인하고 한 트랜잭션으로 반영한다. DB 오류가 나면 연결을 종료하고 다시 확인한다. MySQL의 `--force` 옵션은 사용하지 않는다.
- `name`과 보정 보호용 메타데이터만 변경한다. `manual_override=true`, `translation_source=MANUAL_NAME_CORRECTION`, 버전 증가를 적용한다.
- 이름만 검수했으므로 주소까지 검수했다는 `REVIEWED` 상태로 올리지 않는다. 기존 주소 상태·출처, 번역 시각, 검수 시각, 원문 해시는 보존한다.
- 기존 자동 번역 경로는 수동 보정 행을 덮어쓰지 않는다. 보호는 이름 하나가 아닌 해당 언어 행 전체에 적용된다. 이후 원문이 달라지면 기존 해시 불일치 정책에 따라 한국어로 대체되며 별도 검토가 필요하다.

## 검증과 적용

이 스크립트는 **SQL만 출력**하며 DB에 접속하지 않는다. PR·CI가 통과해도 운영 반영을 뜻하지 않는다. 운영 변경 승인 후 별도의 제한된 DB 세션에 전달한다. API/웹 앱 재배포나 스키마 마이그레이션은 필요 없다.

```sh
# 읽기 전용 기본값: eligible=4, cacheTriggerPresent=true, changed=0 확인
python3 -B scripts/translation_name_corrections.py

# 승인 후 반영용 SQL: changed=4 확인
python3 -B scripts/translation_name_corrections.py --mode apply

# 필요할 때만 복구용 SQL: 정확히 이번 보정 직후 상태여야 4행 복구
python3 -B scripts/translation_name_corrections.py --mode rollback
```

직접 DB 클라이언트를 연결하는 명령이나 암호는 저장소·로그·채팅에 남기지 않는다. 적용 직전에도 읽기 전용 확인을 반복한다. `changed=0`은 성공으로 간주하지 말고 충돌 원인을 확인한다. 재실행으로 이미 처리된 행이 다시 변경되지는 않는다.

복구는 기존 이름·출처·수동 보호 여부를 되돌리되 버전은 감소시키지 않는다. 그 사이 다른 사람이 수정했으면 4행 모두 복구하지 않는다. 원래부터 있었던 다른 데이터는 되돌리지 않는다.

## 캐시와 기존 URL

기존 `cache_toilet_translation_update` 트리거가 있을 때만 수정한다. 보정으로 생성되는 두 시설의 기존 캐시 갱신 이벤트를 사용하며 전체 캐시 삭제·사이트맵 재제출은 하지 않는다. 전달 완료와 실제 영어·중국어 응답을 확인해야 운영 완료다.

웹 상세 주소는 이름이 바뀌어도 시설 ID로 조회한다. 소스상 이전 이름의 주소는 현재 이름 주소로 영구 이동하고 canonical도 현재 이름을 가리킨다. 실제 운영 응답에서 새 제목·canonical·옛 주소 이동을 별도로 확인한다.

검증은 Python 단위 테스트 및 GitHub Actions의 일회용 MySQL 8.4 서비스에서 진행한다. 운영 미니 PC에는 시험 DB나 Docker를 추가하지 않는다. 대상 4행 반영·재실행·복구, 한 행 충돌 시 전체 중단, 캐시 이벤트, 주소·다른 언어·원문 불변, 기존 자동 번역 재실행의 보호를 확인한다.
