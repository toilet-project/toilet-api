# 계정 처리와 LOCAL 복원 검사의 공통 잠금

상태: 구현·로컬 검증 중. 운영 배포 및 탈퇴·복구 활성화는 하지 않았다.

## 트랜잭션 경계

- 탈퇴, 보관기간 내 복구, 즉시 파기 요청: 잠금 획득 → SQL 트랜잭션 시작 → 기존 처리 → 커밋/롤백 → 잠금 해제.
- 보관기간 경과 계정의 OAuth 로그인: 기존 OAuth 트랜잭션에 참여한다. 잠금은 대기 없이 획득을 시도하고 `afterCompletion`에서 해제한다. OAuth 호출자는 예외를 삼키지 않아야 한다.
- 배치 파기도 같은 잠금을 SQL 커밋/롤백까지 유지한다. 잠금이 없거나 사용 중이면 처리를 시작하지 않는다.
- 일반 로그인, 닉네임 수정, 읽기 조회를 이 잠금에 포함시키지 않는다.

`LocalMaintenanceLease`는 Java FileChannel의 POSIX record lock을 사용한다. 복원 Python 도구는 동일 파일의 `fcntl.lockf`를 사용해야 하며 `flock`으로 대체하면 안 된다. 별도의 백업 `flock`은 유지한다. 잠금 파일은 앱이 자동 생성하거나 교체하지 않는다.

복원 검사가 긴 동안 탈퇴·복구는 503 재시도 안내를 반환할 수 있다. 공개 기능 활성화 전에 이 운영 영향을 확인해야 한다.

## 배포 전 조건

- [x] API 트랜잭션·로그인 연동 표적 테스트 27건 통과
- [x] 배치와 동일한 공통 잠금 구현 사용
- [x] 일반 트랜잭션의 잠금 해제는 커밋/롤백 이후임을 검증
- [x] 기존 OAuth 트랜잭션 참여 시 커밋/롤백까지 유지 검증
- [ ] Docker 사용 가능 환경에서 API 전체 회귀 테스트 통과
- [ ] API·배치·복원 도구가 같은 잠금 파일을 보는 배포 구성 검증
- [ ] 잠금 디렉터리·파일을 명시적 권한으로 설치하고 컨테이너 마운트 검증
- [ ] 파기 완료 증거 수집 경로 등 추가 대장 작성자의 잠금 참여 확인
- [ ] 운영 적용 승인 및 적용 후 읽기 전용 점검

2026-09-10 API 전체 로컬 실행: 총 228건, 통과 216건, 건너뜀 8건, Docker 부재로 MySQL 컨테이너 초기화 실패 4건. 전체 통과가 아니다. 실제 MySQL 경로는 별도 검증이 남아 있다.

후속 검증: 초기화 실패했던 MySQL 클래스 4개를 Linux의 제한된 임시 Testcontainers 환경에서 별도 실행해 14건 모두 통과했다. `scripts/export-isolated-tests.init.gradle`은 테스트 산출물만 내보내며 `scripts/IsolatedRegressionRunner.java`는 해당 4개 클래스만 선택한다. 한 환경에서 전체 Gradle 검사를 다시 실행한 결과는 아니다.

`render-maintenance-deployment.mjs`는 기존 점검 상태를 유지하는 배포 후보만 생성한다. 현행 deploy workflow는 변경하지 않았다. 새 `maintenance-preflight`의 사전 설치와 실제 경로 검증을 별도로 요구한다.
