# 소셜 프로필 사진 저장·접근 설계

[WEB #203](https://github.com/toilet-project/toilet-web/issues/203)의 API 구현. 기본 OFF인 준비 코드이며 이 문서를 운영 활성화·고지 완료 근거로 사용하지 않는다.

## 사용자 동작

마이페이지 프로필 수정 톱니에서 `소셜 사진 사용`을 선택하면 다음 정상 소셜 로그인 때 사진을 확인한다. 최초 가입의 필수 동의가 끝나기 전에는 사진을 가져오지 않는다. 사진 사용과 타인에게 공개하는 설정은 별개이며 기본값은 모두 꺼짐이다. 기존 회원을 자동으로 사진 수집에 등록하지 않는다.

사용 선택 후 기본 공개 범위는 본인만 보기다. 공개하면 공개 리뷰 작성자 사진으로 표시한다. 비공개 전환은 이미 저장된 파일을 삭제하지 않으며 본인에게는 계속 표시한다. 사진 사용 중단·탈퇴는 파일 연결을 제거한다. 복구용 3개월 선택 보관에도 사진은 포함하지 않고, 복구 후 필요하면 다시 사용을 선택한다. 사용자 직접 업로드·편집 API는 없다.

## 이미지와 저장소

- 신뢰하는 Google/Kakao 이미지 호스트의 URL만 받아 HTTPS로 요청한다. 리다이렉트는 따르지 않는다. 미지원 호스트는 로그인 성공을 유지하면서 사진만 기본값으로 둔다.
- 2MiB 다운로드 제한, 8초 HTTP 제한, 400만 픽셀, JPEG/PNG/정지 WebP만 허용한다.
- 원본은 JVM/변환 프로세스 메모리에서만 사용한다. 변환기는 stdin/stdout을 사용하고 파일을 만들지 않는다. EXIF 방향 적용 후 정사각형으로 자르며 최대 256px로 줄인다. 작은 사진은 확대하지 않는다.
- WebP 품질 80, 최대 100KB 결과만 비공개 전용 R2에 저장한다. EXIF·ICC·원본 URL을 저장하지 않는다. 파일명은 무작위 UUID다.
- Linux 변환 프로세스는 주소 공간 256MiB·CPU 4초·실행 8초 제한을 사용한다. 컨테이너에 배포한 Pillow/WebP 지원을 CI에서 확인한다.
- 단일 사진 작업 스레드와 최대 32개 대기열을 사용한다. 동일 회원의 중복 작업은 합친다. 삭제 정리도 별도 사진 스레드에서 실행해 기존 캐시 스케줄러를 막지 않는다.
- 원본 URL의 해시와 확인 시각으로 동일 소스의 재로그인 재확인을 24시간으로 제한한다. URL이 변경되면 재확인하고, 변환된 내용이 같으면 중복 업로드하지 않는다. 처리 실패 후에는 다음 로그인 때 재시도한다.

## API 계약

| 경로 | 동작 |
| --- | --- |
| `GET /api/v1/auth/me/photo` | 본인 설정과 변환 사진 버전. 기능 OFF이면 `available:false` |
| `PATCH /api/v1/auth/me/photo` | 본인 설정. JSON `useSocial`, `publicPhoto` 필수. ACTIVE 회원과 허용 Origin만 수락 |
| `GET /api/v1/auth/me/photo/image?version=…` | 본인의 현재 버전에 해당하는 사진만 반환 |
| `GET /api/v1/toilets/{toilet}/reviews/{review}/photo` | 공개 리뷰의 현재 작성자가 ACTIVE이고 사진 공개를 선택했을 때만 반환 |

사진은 R2 주소·서명 URL을 클라이언트에 노출하지 않고 API가 전달한다. 공개 리뷰 경로로 회원 ID를 노출하지 않는다. 사진 응답·설정·오류는 브라우저/CDN `no-store`로 처리하며 Next.js 이미지 최적화 캐시도 사용하지 않는다. R2 읽기 후 현재 접근 권한을 다시 확인한다. 비공개 전환 이후에 시작하는 새 요청은 기존 공개 리뷰 URL로 사진을 받을 수 없다. 이미 완료된 다운로드·타인 기기에 남은 사본은 회수할 수 없다.

따라서 사진 요청 시 미니 PC가 작은 파일을 전달하는 트래픽이 발생한다. R2 직결 CDN의 무서버 전송 방식은 아니다. 추후 Worker 전달로 바꾸더라도 공개 상태 확인을 생략하거나 장기 서명 URL을 발급하면 안 된다. 이 단계는 즉시 권한 확인을 우선한다.

## 탈퇴·삭제·경합

계정의 SQL 행 잠금과 설정 세대 번호, `auth_version`을 확인한다. 설정 변경·탈퇴 전에 시작된 사진 저장은 최신 결정을 덮어쓸 수 없다. 탈퇴 트랜잭션은 사진 연결을 제거하고, 회원 최종 삭제 시 FK CASCADE가 API·배치·복원 후 재파기에서도 동일하게 동작한다. 공통 회원 파기 SQL의 조건 분기를 추가하지 않는다.

R2 쓰기 전에 무작위 파일 경로를 객체 대장에 먼저 기록한다. 대장에는 회원 ID·원본 URL이 없다. 쓰기 실패·DB 갱신 실패·프로세스 종료로 남은 파일도 추후 회수할 수 있다. 참조가 없고 생성 후 5분이 지난 객체를 정리 대상으로 하며 1분마다 최대 5개를 시도한다. 정상 상태의 단일 삭제는 대략 5~6분 후 파일 제거 대상이 되고, 적체나 장애 시 늦어질 수 있다. 접근 차단과 실제 파일 삭제 완료를 구분한다. 삭제 실패는 대장을 유지해 재시도한다.

되돌리기는 웹 기능을 먼저 끈다. 이미 수집한 사진이 있으면 API 사진 저장소 설정과 삭제 정리를 유지해 파기한다. 정리 전에 API 기능·저장소 자격증명을 일괄 제거하지 않는다. 회원 DB만 복원하는 경우에도 기존 계정 파기 대장을 재적용하고 사진 연결·R2 잔여 객체를 점검해야 한다.

## 배포 전 확인

CI의 `Profile photo validation`은 Pillow를 설치하고 `PROFILE_PHOTO_CONVERTER_TEST=true`로 실제 Java→Python 변환 검사를 강제한다. 사진 권한·삭제 검사는 H2와 폐기 가능한 MySQL 컨테이너에서 같은 시나리오를 실행하며 전용 CI는 MySQL 검사가 건너뛰어지면 실패한다. 일반 API 검사는 별도 Python 설치를 요구하지 않도록 변환 프로세스 검사만 제외한다. 로컬에서 변환 검사를 재현할 때도 이 환경 변수와 Pillow 설치가 필요하다.

- `PROFILE_PHOTO_ENABLED=false`가 기본이다. 기존 로그인 권한과 계정 상태를 바꾸지 않는다.
- 전용 비공개 버킷, 공개 도메인/r2.dev 비활성, 이 버킷만 읽기·쓰기·삭제 가능한 자격증명을 준비한다. 기존 ISR·회원 보호 기록 버킷을 재사용하지 않는다.
- 환경 변수: `PROFILE_PHOTO_R2_ENDPOINT`, `PROFILE_PHOTO_R2_BUCKET`, `PROFILE_PHOTO_R2_ACCESS_KEY_ID`, `PROFILE_PHOTO_R2_SECRET_ACCESS_KEY`. 변환기 기본은 컨테이너의 `python3`, `/app/normalize_profile_photo.py`다.
- Kakao 앱의 사진 동의항목 설정을 확인한 후 `KAKAO_LOGIN_SCOPES`에 `profile_image`를 포함한다. 기본값은 기존 `profile_nickname, account_email`을 유지한다. Google은 기존 `profile` 응답을 사용한다.
- V13 추가 테이블을 격리 MySQL과 배포 후보에서 검증한다. 기존 회원·리뷰 플래그 및 환경 변수를 보존하는 배포 절차를 사용한다.
- 웹 `NEXT_PUBLIC_PROFILE_PHOTO_ENABLED=true`는 API·사진 고지·실계정 인수 준비 후 빌드에 적용한다. 기존 리뷰 API 빌드 게이트도 함께 충족해야 공개 리뷰 UI가 표시된다.
- 현재 리뷰 검증용 preview proxy를 사진에 자동 재사용하지 않는다. 사진 경로의 허용·인증·캐시 정책을 별도로 확인해야 한다.
- 버킷 위치와 실제 계약 정보에 맞춘 수집 목적·항목·보관/삭제·처리 수탁자·국외 처리 고지를 확정한다. 아래 검토 초안은 그 확인을 대신하지 않는다.
- 합성 사진의 실제 R2 쓰기/읽기/삭제, 컨테이너 변환, Origin 차단, 실계정 Google/Kakao 미동의·사용·중단, 비공개 전환과 실제 휴대폰 인수를 마친다.
- 객체 잔여 수·최고 대기 시간과 저장량/Class A·B 사용량을 운영 감시에 연결한다. 이번 단위 테스트 통과를 실제 저장소 삭제·비용 측정 완료로 보지 않는다.

## 고지 검토 초안

목적: 사용자가 선택한 소셜 사진을 본인 프로필 및 선택적으로 공개 리뷰에 표시. 항목: 변환된 소셜 사진·공개 설정·갱신 정보. 원본은 변환 후 보관하지 않는다. 사용 선택은 기본 미선택이며 거부해도 기본 아바타로 서비스를 이용한다. 사용 중단·탈퇴 시 접근을 차단하고 비공개 파일을 삭제 대상으로 처리하며 저장소 장애 시 재시도한다. 공개 설정은 이용자의 선택에 따르며 이미 전달된 사본은 회수할 수 없다.

저장/처리 사업자·저장 국가·전송 경로·연락처·고지 시행 시각·필요한 동의 방식은 실제 계약과 배포 구성에 맞춰 추가 확정해야 한다. R2의 `apac` 힌트는 국내 저장 보장이 아니다. 현재 공개 개인정보처리방침은 이 준비 PR에서 변경하지 않는다.
