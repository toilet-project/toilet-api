# 분석 이벤트의 봇 분류

새로 수집하는 이벤트만 `BOT`(자동화 신호 있음), `UNFLAGGED`(신호 미탐지)로 구분한다. 기존 기록은 `LEGACY`로 보존한다. 출처 없음 전체를 봇으로 보거나 과거 통계를 임의 수정하지 않는다.

## 조회 기준

- 관리자 봇 제외는 기본 켜짐이다. 일별 장기 집계도 봇을 제외한다.
- 봇 포함은 최근 35일 원본 이벤트에만 제공한다. 봇 이벤트도 같은 보존 기간을 따른다.
- 브라우저 정보에 나타난 자동화 신호이지 공식 검색 봇의 신원 인증이 아니다. IP·브라우저 정보 원문은 추가 보관하지 않는다.
- Nginx 요청 수와 브라우저 분석 이벤트는 다른 지표다. 서버 요청 수를 방문자·페이지뷰에서 차감하지 않는다.

## 안전한 운영 적용

1. 분류 컬럼 유무를 모두 지원하는 관리자 조회 기능을 먼저 배포한다.
2. API 이미지는 기존 계정·캐시·배치 설정을 보존하는 이미지 교체 절차로 배포한다. V33은 기존 기록에 LEGACY 기본값을 추가하는 호환 마이그레이션이다. 이때 봇 보관은 기본 꺼짐이다.
3. 관리자 제외 조회와 API 건강 상태·스키마를 검증한다.
4. `scripts/service_analytics_release_transition.py`의 `--feature bot-retention`을 사용해 check 후 activate 한다. 실행 중인 API·배치·관리자 이미지 커밋을 고정하고, 활성화에는 `--admin-compatible-confirmed --apply-approved --deployment-freeze-confirmed`가 필요하다. 기존 운영 잠금·개인정보 처리 상태 검증·설정 백업·실패 시 설정 복구를 그대로 사용한다.
5. 변경 가능한 설정은 `SERVICE_ANALYTICS_RETAIN_BOT_EVENTS=true` 하나뿐이다. 다른 설정 파일과 배치 컨테이너는 바꾸지 않는다. 비밀값과 원본 이벤트를 출력하지 않는다.

되돌릴 때는 같은 절차의 deactivate로 보관을 먼저 끈다. 이미 저장된 봇은 삭제하지 않는다. 이를 제외하지 못하는 이전 관리자·집계 버전으로 되돌리지 않는다. 수집 시점 이후의 자연 유입으로 분류를 확인하며 운영 통계에 시험 이벤트를 넣지 않는다.
