# 위치 기반 리뷰 — API·DB 구현 및 활성화 전 확인

개발 4주차: 2026-09-07~09-13. 최초 결정: 2026-09-11. 서버 구현: 2026-09-12.
연결: API #105 · WEB #205 · 정책 후속 DOCS #96.

## 현재 상태와 범위

API와 추가형 Flyway V12 마이그레이션 후보를 구현했다. 운영 DB에는 실행하지 않았다.
`REVIEWS_ENABLED=false`가 기본이며 읽기·쓰기 모두 503으로 닫힌다. 기존 공개 디자인 프리뷰는 계속 메모리 저장이며 이 변경만으로 실제 저장으로 전환되지 않는다. 웹 PR #206에 API 연결 후보를 추가했으며, 빌드 시 별도로 선택하는 프리뷰 전용 모드이다. 실제 API↔DB 격리 환경 인수·운영 DDL·활성화는 아래 미완료 항목으로 구분한다.

회원정보 이외 운영/감사/제보 전체 정리, 기존 보관정책 확대, 운영 서버 설정 변경은 포함하지 않는다.

## 최신 사용자 결정

- 만족도·청결도 각 정수 1~5, 화장지 유무 필수. 대기시간 기본 0분, 0~60분/10분 단위이며 60은 1시간 이상. 별도의 혼잡도 입력은 없다.
- 자유글 선택, Unicode 코드포인트 200자. 글·별점·선택값은 작성자 정보 지우기 후에도 보존한다. 자유글 잔존 약관과 개인정보 요청 통로는 DOCS #96 후속이며 아직 공개하지 않는다.
- 신규 작성: 로그인한 ACTIVE·필수 정책 동의 계정, DB에 존재하는 화장실의 현재 좌표로 150m 이내, 위치 정확도 50m 이하, 측정 후 5분 이내. 5초를 초과한 미래 측정도 거부한다.
- 2026-09-12 추가: **같은 회원·같은 화장실은 최초 작성 후 24시간에 1건**. 한국시간 자정 초기화가 아니라 이동 시간창이다. 다른 화장실은 별도로 계산한다. 기존 리뷰 수정은 가능하며 수정 시각으로 24시간을 연장하지 않는다.
- 24시간 안에 연결된 본인 리뷰가 있으면 ‘작성한 리뷰 내역이 있습니다’ 안내와 내 리뷰 해당 항목 펼침으로 이동한다. 기존 리뷰 확인에는 새 위치 검사를 요구하지 않는다. 작성자 정보를 지운 리뷰는 다시 열거나 연결하지 않고, 다음 작성 가능 시각까지만 재작성을 막는다.
- 수정·작성자 연결 해제: 동일 회원, 최초 작성부터 7일 미만. 수정으로 마감이 연장되지 않으며 재방문은 요구하지 않는다.
- **본인이 휴지통 → 최종 확인한 그 리뷰 1건만** 작성자 '익명', 내 리뷰에서 제외. 계정 닉네임·다른 리뷰 작성자·제보 작성자는 변경하지 않는다.
- 실제 회원 탈퇴의 작성자는 '탈퇴한 사용자'. 복구 기간 중 계정 연결은 유지되어 같은 계정 복구 시 내 리뷰로 돌아온다. 이미 명시적으로 연결을 해제한 리뷰는 돌아오지 않는다.
- 내 리뷰 기본 최근 7일, 30일/전체/직접 날짜, 최초 작성 최신순, 10건씩 추가. 날짜는 한국시간이고 종료일까지 포함한다. 내 리뷰 카드 평균은 (만족도+청결도)/2, 한 자리 소수점이며 원점수도 보존한다.

## DB

| 테이블 | 저장하는 내용 | 연결 해제·회원 최종 파기 |
| --- | --- | --- |
| toilet_review | 시설 FK, nullable 회원 FK, 명시적 익명 전환 여부, 별점 2개·휴지·대기·글, 생성/수정 시각, 버전 | 휴지통: 해당 회원 FK NULL + 익명 표시. 계정 파기: FK ON DELETE SET NULL, 본문·평가 유지 |
| toilet_review_submission | 회원별 UUID 요청키·내용 해시·리뷰 FK | 해당 리뷰 휴지통 시 같은 트랜잭션에서 제거. 계정 파기 시 CASCADE |
| toilet_review_write_guard | 회원별 마지막 생성 시각·한국 날짜·하루 생성 횟수 | 특정 리뷰/시설/위치 연결 없음. 휴지통으로 도배 제한 초기화 불가. 계정 파기 시 CASCADE |
| toilet_review_toilet_guard | 회원·화장실별 다음 작성 가능 시각 | 리뷰 ID·본문은 저장하지 않음. 휴지통으로 24시간 제한 초기화 불가. 회원 최종 파기 시 CASCADE |

기기 좌표·정확도·측정 시각·IP·기기 정보·이메일·닉네임 사본은 네 테이블에 저장하지 않는다.
화장실별 제한 메타데이터도 회원과 시설의 관계를 담으므로 완전한 익명 정보라고 주장하지 않는다. 만료한 값은 판정에서 즉시 제외하고, 해당 회원의 다음 성공한 신규 작성 트랜잭션에서 제거한다. 그때까지 물리적으로 남을 수 있으며 비활성 회원의 만료 메타데이터 정기 정리·보관 고지는 운영 활성화 전 확정한다. 이 값으로 익명 리뷰를 특정하거나 복구하는 API는 제공하지 않는다.
닉네임은 조회 시 회원 테이블에서 가져온다. 위치는 요청 본문에서만 검사하고 로그·URL·해시에 넣지 않는다.
리뷰 시설과 생성 시각 자체가 이용 장소 정보를 나타낼 수 있으므로 '위치정보를 전혀 처리하지 않는다'고 안내하지 않는다.

MySQL CHECK는 정수 별점·휴지 boolean·대기시간·버전 범위를 제한한다. ON DELETE SET NULL 대상 열을 CHECK에서 함께 참조할 수 없는 MySQL 제약 때문에 명시적 익명 전환과 FK NULL은 서버의 단일 UPDATE로 처리한다.

## API 계약

| 메서드·경로 | 용도 |
| --- | --- |
| POST /api/v1/reviews | 실제 작성. Idempotency-Key UUID 필수, 입력 내용과 position 본문 |
| GET /api/v1/reviews/creation-status?toiletId={id} | 본인 화장실별 작성 빈도 판정. canCreate·existingReviewId·nextAllowedAt 반환, 인증 필수 |
| GET /api/v1/reviews/me | 본인 목록, from/to YYYY-MM-DD·cursor·size(기본 10, 최대 50) |
| GET /api/v1/reviews/{id} | 본인 전문. 타인/연결 해제 리뷰는 동일한 404 |
| PATCH /api/v1/reviews/{id} | version + 내용 전체. 위치는 재요구하지 않음 |
| POST /api/v1/reviews/{id}/detach-author | version + acknowledgeContentRetention:true 필수 |
| GET /api/v1/toilets/{id}/reviews | 공개 작성자 표시·평가·본문 목록, cursor·size |
| GET /api/v1/toilets/{id}/reviews/summary | 공개 카드용 집계 데이터 |

작성 본문:

```json
{
  "toiletId": 1,
  "satisfaction": 4,
  "cleanliness": 5,
  "paper": true,
  "waitMinutes": 20,
  "comment": "합성 리뷰 예시",
  "position": {
    "latitude": 36.3,
    "longitude": 127.3,
    "accuracyMeters": 10,
    "measuredAt": "2026-09-12T00:00:00Z"
  }
}
```

수정은 위의 내용 필드와 `version`을 보내며 `toiletId` 변경을 지원하지 않는다.
서버 시각은 UTC Clock으로 판단하고 DB DATETIME은 기존 서비스와 동일한 한국시간. 응답은 +09:00 오프셋을 명시한다.
ID는 응답에서 문자열, 페이지는 `{items,nextCursor,hasMore}`. 최초 작성시각+ID 커서로 동시 등록/수정 시 offset 페이지 밀림을 피한다.
`from/to`를 모두 생략하면 전체이며 웹의 기본 7일 범위는 웹에서 명시하여 요청한다.
공개 응답에 회원 ID·이메일·요청키·내용 해시·좌표를 넣지 않는다.

`creation-status.canCreate`는 화장실별 24시간 제한에 대한 결과이지 위치·전체 계정 도배 제한을 통과했다는 뜻은 아니다. `existingReviewId`는 아직 연결된 본인 리뷰에만 제공한다. 명시적으로 익명 전환했다면 null이다. 생성 시에도 다시 검사하며, 중복은 409 `{error:{code:"REVIEW_ALREADY_EXISTS",message,existingReviewId,nextAllowedAt}}`로 반환한다. 웹 실제 API 연결 시 진입 사전 조회와 저장 시 409 모두 같은 기존 리뷰 이동에 연결해야 한다. 사전 조회 실패를 ‘작성 가능’으로 취급하면 안 된다.

## 동시성·권한·도배 제한

1. 기능 플래그 확인 → app_user FOR UPDATE → ACTIVE·JWT auth_version·필수 동의 확인.
2. 신규 등록 요청키 조회: 같은 회원·동일 키·같은 내용은 기존 리뷰 반환. 다른 내용의 키 재사용은 409. 응답 유실 재시도는 별도 신규 방문으로 기록하지 않는다.
3. DB 시설 좌표 잠금 → 같은 화장실 24시간/기존 본인 리뷰 판정 → 거리·정확도·신선도 → 계정별 제한 → 리뷰/요청키/횟수/화장실별 제한을 한 트랜잭션에 저장. 동시에 다른 요청키로 전송해도 1건만 생성된다.
4. 같은 화장실 24시간 제한 외에 기존 기본 60초 간격·계정 전체 하루 10건 설정은 유지한다. 후자의 하루는 한국 날짜 기준이며 시설별 이동 24시간과 다르다. 운영 활성화 때 계정 전체 제한값을 확정한다.
5. 수정/연결 해제는 회원 행 잠금과 version 조건으로 동시 요청을 직렬화한다. 오래된 화면은 409이며 타인 요청은 404. 서버에서 7일 경계를 판정한다.
6. 휴지통은 원문·작성 시각·평가 시각을 갱신하지 않는다. 닉네임 NULL과 요청 연결 제거는 같은 트랜잭션이다.
7. 모든 리뷰 응답은 private,no-store. 쿠키 인증 쓰기는 허용된 서비스 웹 Origin만 받는다. 관리자 도메인·불명확한 Origin을 자동 허용하지 않는다.
8. JSON의 소수 별점/분/ID/버전과 문자열 boolean을 리뷰 요청에 한해 거부한다. 파싱 오류에는 좌표·원문을 되돌려주지 않는다.

브라우저 위치는 사용자가 조작할 수 있다. 서버 검증도 실제 방문을 암호학적으로 증명하지 않는다. 지도 중심·IP·검색 주소를 사용자 위치로 대신하지 않는다.

## 집계 초기안

- count: 작성자 연결 여부와 무관한 리뷰 수.
- rating: 기존 카드 의미를 유지한 만족도 평균. averageRating: 만족도·청결도 합산 평균. 둘 다 한 자리 소수점.
- paperPercent/paperSampleCount: 최초 작성 최근 7일의 화장지 있음 비율/표본 수. 표본 없음은 null/0.
- latestWaitMinutes/latestWaitAt: 최초 작성 최근 1시간 내 최신 리뷰. 오래된 기록은 null, 0분과 구별한다.
- 수정·익명 전환으로 오래된 기록이 실시간 이용 기록이 되지 않는다. 혼잡 임계값은 임의로 만들지 않고 대기 분만 반환한다.
- 위 집계 시간창은 서버 구현 시작값이며 운영 공개 전에 웹 문구와 함께 확정한다.

## 기존 회원 파기·복원 호환

기존 API/배치 공통 `AccountErasureSql`과 `AccountErasureRestore` 코드를 바꾸지 않았다.
회원 삭제 시 V12의 SET NULL/CASCADE가 리뷰 참조를 정리하므로, 실제 회원 파기 대장을 이용하는 검증된 복원 재처리에도 동일하게 적용된다.
구 백업에 V12 테이블이 없는 경우에는 기존 파기 SQL이 새 테이블을 참조하지 않아 계속 동작한다.

**별도 미해결 경계:** 회원 탈퇴 없이 리뷰 1건만 익명 전환한 뒤, 그 이전의 전체 DB 백업을 복원하면 과거의 리뷰-회원 연결이 되살아날 수 있다. 기존 대장은 회원 파기 단위이므로 리뷰 1건의 연결 해제 증적으로 사용하면 안 된다. 복원 시 이 연결을 다시 제거할 최소 증적/검증 방식을 정하기 전 '어떤 백업 복원에서도 연결 복구 불가'를 보장하지 않는다. 운영 활성화 전 확인 항목이다.
